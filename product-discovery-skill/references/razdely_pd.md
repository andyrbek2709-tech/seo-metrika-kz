# Разделы проектной документации и где «заваливают» на экспертизе

Назначение файла — дать аналитику доменную опору: какие разделы ПД сложнее всего пройти
на Госэкспертизе и почему. Это фокус продуктовой гипотезы: **боль рынка не в «экспертизе
вообще», а в конкретных разделах, по которым летят замечания и отказы.** Там, где раздел
трудный, формализуемый и текстово-нормативный, — там инструмент на Claude максимально
полезен. Читать перед заполнением `assets/report_template.md`, разделы 3–4.

## Состав ПД (ориентир: ПП РФ №87 / аналог в РК)

| Шифр | Раздел | Сложность экспертизы |
|---|---|---|
| ПЗ | Пояснительная записка | низкая |
| ПЗУ / СПОЗУ | Планировочная организация участка | средняя |
| АР | Архитектурные решения | средняя |
| **КР (КЖ/КМ)** | **Конструктивные решения, строительные расчёты** | **высокая** |
| ИОС | Инженерное оборудование и сети (ЭОМ/ВК/ОВ/СС/ГСВ/ТХ) | высокая |
| ПОС | Проект организации строительства | средняя |
| ООС | Охрана окружающей среды | высокая |
| **МОПБ (ПБ)** | **Мероприятия по обеспечению пожарной безопасности** | **очень высокая** |
| ОДИ | Доступ маломобильных групп (МГН) | средняя |
| ЭЭ | Энергоэффективность | средняя-высокая |
| СМ | Сметная документация | высокая |

## Самые «отказные» разделы (приоритет для продукта)

1. **МОПБ — пожарная безопасность.** Лидер по замечаниям. Причины: пересечение
   множества норм (противопожарные расстояния, пути эвакуации, СОУЭ, пожаротушение,
   расчёт пожарных рисков), частые правки норм, субъективность трактовок. Запросы-боль:
   «замечания по мопб», «отказ по пожарной безопасности», «как пройти экспертизу
   пожарной безопасности», «расчет пожарных рисков пример».
   **Claude-fit:** очень высокий — это работа с нормами и текстом, сверка раздела с
   требованиями, генерация/проверка расчётной части и пояснительной.

2. **КР — строительные расчёты / конструктив.** Расчёт нагрузок, железобетон,
   металл, основания/фундаменты, сейсмика, прогрессирующее обрушение. Замечания — из-за
   ошибок в расчётных предпосылках, несоответствия расчётной схемы и чертежей, неполноты.
   **Claude-fit:** высокий на проверке логики/полноты/соответствия нормам и оформления
   расчётной записки; собственно численный расчёт — за профильным ПО (Claude проверяет
   вход/выход и обоснование, а не считает МКЭ).

3. **Сметы.** Несоответствие расценок, объёмов, метода. Формализуемо → высокий Claude-fit.

4. **ООС, Энергоэффективность, Инсоляция/КЕО.** Нормативно-расчётные разделы со
   стабильным потоком замечаний — вторая волна продуктовых возможностей.

## Как использовать в анализе

- В `cluster_demand.py` темы заданы **по разделам** (МОПБ, КР, смета…) — смотри, какой
  раздел даёт больше спроса и больше запросов-боли (намерение `problem`).
- Для каждого «отказного» раздела в отчёте формулируй продукт как «помощник по разделу X»:
  вход (черновик раздела + применимые нормы) → выход (список несоответствий + правки).
- Помни границу: Claude силён на нормах, тексте, проверке полноты и логики; тяжёлый
  численный расчёт оставляй профильному ПО, а Claude — на обвязке и обосновании.
